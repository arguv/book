Large Language Model (LLM)
  • The LLM itself is a deep learning model.
  • LLM describes a family of language-oriented AI models.
  • Multimodal describes a model's capability to process different data types.
  • LLM (Large Language Model) — text-only. Takes text in, produces text out. Examples: GPT-3, Llama 2, Mistral 7B.
  • Multimodal LLM (MLLM / VLM) — takes multiple modalities as input (text + images, sometimes audio/video) and typically outputs text. Examples: GPT-4o, Gemini, Claude 3.5 Sonnet, LLaVA, Qwen-VL.
  • By architecture:
  • Dense Transformers, Mixture-of-Experts (MoE)
  • State Space Models (SSM)
  • Within multimodal, common subtypes:
  • Vision-Language Models (VLM) — image + text → text (most common)
  • Audio-Language Models — speech/audio + text → text
  • Omni-modal — any combination of text/image/audio/video in and out (e.g., GPT-4o)
  • Video-Language Models — video + text → text
LLM
  • Capabilities: Choose a model that can understand documents and answer questions.
  • Technical Specifications: Check whether its context window is large enough for the documents.
  • Inference Settings: Configure the response length and available reasoning settings.
  • Capabilities | What the LLM can do | Reasoning, coding, understanding images, generating text
  • Technical Specifications | The model's technical characteristics and limits | Context window, token limits, supported modalities
  • Inference Settings | How the model generates responses | Temperature, top-p, max output tokens, reasoning effort
Capability
  • Reasoning - Solve complex logical or architectural problems
  • Coding - Generate and debug Go, Python, PHP
  • Vision - Understand screenshots, diagrams, photographs
  • Text generation - Write emails, reports, documentation
  • Language understanding - Translate and explain text
  • Summarization - Analyze documents and extract information
  • Tool calling - Request web searches, calculations, API operations

Term Full name Purpose
LM Language Model General category of language models

LLM Large Language Model Large-scale language understanding and generation
VLM Vision-Language Model Understand images, text, and sometimes video
ALM Audio Language Model Process audio and language; acronym is less standardized
Video-LLM Video Language Model Understand and reason about video
MLLM Multimodal Large Language Model Process combinations of text, images, audio, etc.
Omni Omni-modal Model Unified processing across several modalities, potentially including text, audio, images and video

  • VLM and Omni terminology is documented by NVIDIA.
  • Important: These are overlapping categories, not a strict hierarchy.
  • SLM vs LLM describes model size.
  • VLM, ALM, MLLM, Omni describe supported modalities.
  • VLA describes vision-language models with action capabilities.
Tokenization

Splits text into units called tokens and maps each token to a numeric ID the model can process.

Character tokenizer

Treats each character as a token. It is simple to understand, though sequences become longer than with word or subword tokens.

Input: character

In a character-level model, the input is a sequence of character IDs that provides context for a prediction.

Target: next character

The expected answer for each input position is the character immediately after it in the original text.

Tensor shapes (block_size = 4)

A block contains four input tokens. A batch of these blocks has shape (batch_size, 4); its targets have the same shape.

PyTorch tensors

Multidimensional arrays that hold model inputs, parameters, and outputs. PyTorch uses them for automatic differentiation.

PyTorch’s CPU build

A PyTorch installation that runs calculations on the CPU without requiring a GPU.

Embeddings

Learned vectors that represent token IDs as numbers a model can work with.

Embedding layer

A lookup table of learned vectors. Given token IDs, it returns their corresponding embeddings.

embedding_dim = 6

Each token embedding has six numbers, so an embedding layer returns vectors of length 6.

nn.Embedding

The PyTorch layer that maps integer IDs to trainable embedding vectors.

Linear layer

A layer that applies a learned weighted sum and an optional bias to transform input features into output features.

Logits

Raw model scores for possible next tokens, before converting them to probabilities.

PyTorch and pytest

PyTorch builds and trains the model; pytest runs automated checks on the code.

Bigram model

A simple model that predicts the next token using only the current token.

Number of predictions

For next-token training, the model makes one prediction at each input position; a four-token block gives four predictions.

Predicted IDs

The numeric token IDs chosen from model scores, which a tokenizer can convert back to text.

Scores for one position

The logits for all possible next tokens at one input position; the vector has one score per vocabulary item.

Linear biases

Trainable values added to a linear layer’s weighted sums, usually one bias per output feature.

Linear weights

Trainable values that determine how strongly each input feature contributes to each output feature.

nn.Linear

The PyTorch module that implements a linear transformation with trainable weights and, by default, biases.

argmax

Returns the index of the largest value. Applied to logits, it selects the highest-scoring token ID.

Kaiming uniform

A weight initialization method that samples values from a range chosen to help signals flow through a network.

Cross-entropy loss

Measures how well predicted scores match the correct token IDs; lower loss means better predictions.

Greedy decoding

Generates text by choosing the highest-scoring next token at every step.

Softmax

Converts logits into probabilities that are nonnegative and sum to 1.

Inspection function

A small helper that prints or displays intermediate values, such as tensor shapes, scores, or predicted IDs, for debugging.

KV cache

Stores attention keys and values from earlier tokens so a transformer can reuse them while generating new tokens.

Feedforward

A neural-network block that transforms each token representation through linear layers and a nonlinear activation.

Dataset preparation

Cleans and tokenizes source text, then splits it into input and target sequences for training and evaluation.

Prediction

The model uses input tokens to produce scores for possible next tokens.

Training

Repeatedly compares predictions with targets and updates model weights to reduce the loss.

Generation

Produces new text one token at a time, feeding each chosen token back into the model.

Attention

Lets each token use relevant information from other tokens in its context. Causal attention restricts a token to earlier positions.

Transformer block

Combines attention and a feedforward network to refine token representations; GPT stacks multiple blocks.

Tiny GPT-style model

A small decoder-only transformer that uses token embeddings, causal attention, and an output layer to predict the next token.

Runtime inspection

Checks values while code runs, such as tensor shapes, loss, logits, and generated tokens, to understand behavior and find errors.
