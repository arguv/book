“What is a class and what is an object?”

A class is a blueprint or definition that describes an object's state and behavior. It defines properties, methods, and how the object should be initialized.

An object is a concrete instance of that class created at runtime. Multiple objects can be created from the same class, each having its own state.

“Why use objects?”

Objects allow us to encapsulate related state and behavior behind a clear interface. This helps us:

  • model domain concepts
  • control access to state
  • reduce coupling
  • make code easier to maintain, test and extend.

By grouping data and the operations that act on that data, we create cohesive, modular units that reflect real-world entities or business rules.

Encapsulation

Don't allow outside code to freely change an object's internal state. Give it controlled methods to do that.

  • private
  • protected
  • public
  • getters/setters
  • methods that enforce business rules
Static Members

A normal property belongs to an object. A static property belongs to the class itself.

  • Normal property = each object has its own value
  • Static property = one value shared at the class level.
  • ✅ static properties
  • ✅ static methods
  • ❌ static classes
Composition vs Inheritance

  • 1. Inheritance — "is-a" relationship
  • Inheritance means one class extends another class and gets its properties/methods.
  • 2. Composition — "has-a" relationship
  • Composition means a class contains/uses another object instead of extending it.

I generally prefer composition over inheritance because it reduces coupling and makes components easier to replace, test, and extend. I use inheritance when there is a clear 'is-a' relationship and the shared behavior genuinely belongs in a base class.

When would you use a trait?
  • Several classes need the same behavior
  • Those classes don't have a natural inheritance relationship
  • You want to avoid duplicating the same code
  • The functionality is small and reusable

What is polymorphism in PHP?

Polymorphism means that different classes can be used through the same interface or parent type, while each class can provide its own implementation of the behavior. For example, different payment classes can implement the same PaymentMethod interface and provide their own pay() implementation. The service only depends on the interface and doesn't need to know which concrete payment class it receives.

What us garbage collection in PHP ?

PHP uses automatic memory management, primarily through reference counting. When an object's reference count reaches zero, PHP can release it. PHP also has a garbage collector that detects and cleans up cyclic references that reference counting alone cannot remove.

SOLID Principles

SOLID = 5 object-oriented design principles:

  • Single Responsibility Principle -> One class should have one responsibility
  • Open/Closed Principle -> Open for extension, closed for modification
  • Liskov Substitution Principle -> Child classes should safely replace their parent
  • Interface Segregation Principle -> Don't force classes to implement methods they don't need
  • Dependency Inversion Principle -> Depend on abstractions, not concrete implementations
  • A class should have one responsibility and one reason to change. It means the class should have one clear job.
  • Software should be open for extension but closed for modification.
  • A subclass should be usable wherever its parent class is expected without breaking the program.
  • Clients should not be forced to depend on methods they don't use. Don't create one huge interface for everything.
  • High-level modules should not depend directly on low-level implementations. Both should depend on abstractions.Depend on interfaces/abstractions rather than concrete classes.
Caching mechanisms — Redis & Memcached

Caching means storing frequently used data in a fast storage layer so we don't need to calculate or fetch it again every time

Redis

Redis is an in-memory data store commonly used for caching.
Because data is primarily kept in RAM, accessing it is much faster than querying a relational database.
Redis can store more than simple key/value strings:

  • Strings
  • Hashes
  • Lists
  • Sets
  • Sorted sets
  • JSON data
  • Expiration/TTL
  • Counters
Memcached

Memcached is also an in-memory key/value cache.
It is intentionally simpler than Redis.
