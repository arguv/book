distributed system

circuit breaker

design pattern, It protects a system. If a service fails, the circuit opens and temporarily stops requests to that service.

A circuit breaker stops repeated failing requests from overloading a system.

CQRS

It's a pattern. Command Query Responsibility Segregation

It separates operations that change data from operations that read data.

It can have different models and can be optimized independently

  • Simple CQRS — only classes/services are separated; there is a single database.
  • Full CQRS — separate databases, synchronization via events, eventual consistency.
Два уровня:

Простой CQRS — разделены только классы/сервисы, БД одна.

Полный CQRS — разные БД, синхронизация через события, eventual consistency.
Saga orchestration

It's a pattern. It's a way to manage a business transaction across multiple services

This is useful in microservice architectures, mostly for payments or order processing.

A central orchestrator coordinates the steps and handles failures or compensating actions.

Temporal

Temporal is a platform for orchestrating complex, long-running business processes. It manages workflow state and helps recover automatically from failures.

lazy loading

Lazy loading means related data is loaded only when it is accessed. It can avoid loading unnecessary data, but if used incorrectly, it can cause the N+1 query problem.

isolation levels

Isolation levels define how much one transaction is isolated from changes made by other transactions.

Common levels are Read Uncommitted, Read Committed, Repeatable Read and Serializable.

index

A data structure that helps the database find rows faster without scanning the whole table.

Can jump directly to the relevant locations instead of scanning every row. So fewer reads, faster lookups, especially on large tables.

slow database query

First, identify the exact query and check its execution plan with EXPLAIN or EXPLAIN ANALYZE. Then look at indexes, joins, filtering, sorting, and data volume. Make one change at a time, then measure again. Never guess or change multiple things blindly.

optimize a slow Doctrine query

I would first check, Symfony Profiler, Doctrine SQL Logger, Doctrine Doctor. Then the query plan, indexes. And if the data is massive, consider async processing, pagination.

background tasks in Symfony

In Symfony, I use Symfony Messenger for background tasks. It sends messages to a queue, such as RabbitMQ, Redis, Doctrine, or SQS, and workers process them asynchronously. For scheduled tasks, I can use Scheduler or cron. In production, workers can be managed with Supervisor or systemd, with retries, failure transport, and memory limits. This way, heavy tasks don't block the user's request.
