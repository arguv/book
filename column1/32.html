How would you design a large-scale data ingestion system?
  • I would separate ingestion from processing using a queue. Independent workers would validate and transform data, then store it in a database. I would add retries, idempotency, rate limiting, monitoring, and horizontal scaling.
What happens if a worker processes the same message twice?
  • I would make processing idempotent using a stable event or package-version identifier, database unique constraints, and upserts where appropriate.
How do you handle millions of database records?
  • I would begin with query analysis and indexing, then consider batching, pagination, appropriate data retention, partitioning when justified, and monitoring query and storage performance.
What is the difference between concurrency and parallelism?
  • Concurrency means managing multiple tasks with overlapping execution. Parallelism means executing tasks simultaneously, often across CPU cores. Asynchronous I/O is useful when many tasks spend time waiting for network responses.
How would you deal with an external API that starts returning errors?
  • Use timeouts, bounded retries with backoff, respect rate limits, avoid overwhelming the service, preserve job state, and monitor failures. For prolonged failures, consider circuit breaking or pausing ingestion.
What is a data pipeline?
  • A data pipeline collects data from one or more sources, validates and transforms it, and stores or delivers it for further processing.
How would you improve a slow ingestion pipeline?
  • First measure throughput, latency, error rates, worker utilization, and database performance. Find the bottleneck before changing concurrency, query patterns, batching, or resources.
What is software supply-chain security?
  • It protects the components and processes used to build and deliver software, including third-party dependencies, package registries, build pipelines, and artifacts.
